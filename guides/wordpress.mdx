## WordPress Plugin Installation

The official AdUnblock plugin is available in the WordPress repository at [https://wordpress.org/plugins/ad-unblock/](https://wordpress.org/plugins/ad-unblock/).

## Method 1: WordPress Admin Installation

### Install from WordPress Repository

1. Go to **Plugins > Add New** in your WordPress admin
2. Search for "Ad Unblock" or visit the [official plugin page](https://wordpress.org/plugins/ad-unblock/)
3. Click **Install Now** and then **Activate**

### Manual Installation

1. Download the plugin ZIP file from your AdUnblock dashboard
2. Go to **Plugins > Add New > Upload Plugin**
3. Choose the ZIP file and click **Install Now**
4. Click **Activate Plugin**

## Plugin Configuration

After installing the plugin, configure it through **Settings > AdUnblock**:

### Basic Settings

- **Verification Code**: Your AdUnblock verification code (from your dashboard)
- **Enable AdUnblock**: Toggle to enable/disable
- **Page Rules**: Choose where to show AdUnblock (all pages, specific URL patterns, categories, or tags)

### Message Settings

- **Message Type**: Overlay, banner, or redirect
- **Message Theme**: Light, dark, or custom
- **Custom Title**: Override default title
- **Custom Message**: Override default message text
- **Button Text**: Customize the action button text

### Advanced Options

- **Exclude Pages**: Specific pages to exclude
- **User Roles**: Which user roles to show messages to
- **Mobile Settings**: Mobile-specific configuration
- **Cache Compatibility**: Settings for caching plugins

## After Installing: Clear Your Caches

The plugin adds the tag to pages WordPress builds from now on. HTML already cached by WP Rocket, LiteSpeed, W3 Total Cache, your host or your CDN still goes out without it, and verification fails on those pages. Clear every layer you run, page cache and CDN both.

## Page Optimizers

The plugin prints the tag with `data-cfasync="false"` and `nowprocket`, ahead of `src`. They keep Cloudflare Rocket Loader and WP Rocket's *Delay JavaScript Execution* from deferring or rewriting it: AdUnblock has to run before your ad code, and either one would load it after your ad requests are already out. Keep the plugin updated and this part looks after itself.

No attribute reaches the rest. If you run any of these, add the script URL to its JavaScript exclusion list, covering minify/combine, defer and delay:

| Optimizer | Where to exclude the script |
| --- | --- |
| WP Rocket *Load JavaScript deferred* | **File Optimization**, its *Excluded JavaScript Files* list |
| LiteSpeed Cache | **Page Optimization**, its JS exclude lists (optimize, defer and delay) |
| Autoptimize | **JS, CSS & HTML**, *Exclude scripts from Autoptimize* |
| W3 Total Cache, Perfmatters, SG Optimizer | Their JavaScript exclusion settings |

Take the URL from the AdUnblock `<script>` tag in your page source (it starts with `data-cfasync="false" nowprocket src=`).
