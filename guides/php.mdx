Server-side script loading packages for PHP applications, providing secure, cached script loading with framework-specific integrations for Laravel and Symfony.

<Warning>
  Every rendered `<script>` tag **must** include a `data-code` attribute set
  to your Account ID (verification code). AdUnblock uses this value to verify
  that the script is running on your registered domain. Find your Account ID
  at the top of your AdUnblock dashboard.
</Warning>

## Expected Remote Response Format

All PHP packages expect the remote URL to return JSON in this format:

```json
["https://example.com/script1.js", "https://example.com/script2.js"]
```

## Laravel Integration

A Laravel package to fetch and render scripts from a remote URL with caching support.

**Repository**: [github.com/adunblock/adunblock-server-tag-laravel](https://github.com/adunblock/adunblock-server-tag-laravel)

### Installation

Install the package via Composer:

```bash
composer require adunblock/server-tag-laravel:^1.0
```

The package will be automatically registered via Laravel's package auto-discovery feature.

<Note>
Version 1.0+ is a stable release and doesn't require lowering `minimum-stability` in your `composer.json`.
</Note>

### Basic Usage

In your Blade template, you can now use the `server_tag` function. Pass your
Account ID (verification code) via the fourth argument, and your site's domain
in the URL:

```php
<!DOCTYPE html>
<html>
<head>
  <title>My Page</title>
  {!!
    server_tag(
      'https://public.adunblocker.com/api/vendor_scripts?domain=' . urlencode(request()->getHost()),
      300,
      null,
      ['data-code' => 'YOUR_ACCOUNT_ID']
    )
  !!}
</head>
<body>
  <h1>My Page</h1>
</body>
</html>
```

The domain lets us move your site alone to a new script host when an ad
blocker rule targets it (see [Fetch Config](/api-reference/fetch-config#query-parameters)).
The cache is kept per URL, so each site of a multi-site install gets its own
answer.

### With Caching

The second argument is the cache duration in seconds (default: `300`):

```php
{!!
  server_tag(
    'https://public.adunblocker.com/api/vendor_scripts?domain=' . urlencode(request()->getHost()),
    600,
    null,
    ['data-code' => 'YOUR_ACCOUNT_ID']
  )
!!}
```

This caches the response for 10 minutes (600 seconds).

### Custom Rendering

Provide a closure as the `render_script` argument to print the tag yourself, for example behind Cloudflare Rocket Loader: Rocket Loader skips a script only when `data-cfasync="false"` comes **before** `src`, and the default tag prints `src` first. The closure receives the script URLs, preferred first. Keep `data-cfasync="false"` and `nowprocket` before `src`, keep `data-code`, and load it with `async`:

```php
<!DOCTYPE html>
<html>
<head>
  <title>My Page</title>
  {!!
    server_tag(
      'https://public.adunblocker.com/api/vendor_scripts?domain=' . urlencode(request()->getHost()),
      300,
      function (array $scripts) {
        if (empty($scripts)) {
          return '';
        }
        return sprintf(
          '<script data-cfasync="false" nowprocket src="%s" async data-code="YOUR_ACCOUNT_ID"></script>',
          e($scripts[0])
        );
      }
    )
  !!}
</head>
<body>
  <h1>My Page</h1>
</body>
</html>
```

### Function Signature

```php
server_tag(
    string $url,
    int $cache_seconds = 300,
    ?callable $render_script = null,
    ?array $script_attributes = null
): string
```

**Parameters:**
- `$url` (string): The remote URL to fetch scripts from
- `$cache_seconds` (int, optional): Cache duration in seconds. Default is `300`
- `$render_script` (callable, optional): Custom rendering function. Receives an array of script URLs and returns an HTML string
- `$script_attributes` (array, optional): Associative array of attributes applied to every generated `<script>` tag. **Must include `'data-code' => YOUR_ACCOUNT_ID`.** Defaults to `['async' => true]`.

- **Blade Helper Function**: Easy-to-use function for templates

- **Security**: XSS protection with proper HTML escaping

## Symfony Integration

A Symfony bundle to fetch and render scripts from a remote URL with Twig integration and caching support.

**Repository**: [github.com/adunblock/adunblock-server-tag-symfony](https://github.com/adunblock/adunblock-server-tag-symfony)

### Installation

Install the bundle via Composer:

```bash
composer require adunblock/server-tag-symfony:^1.0
```

<Note>
Version 1.0+ is a stable release and doesn't require lowering `minimum-stability` in your `composer.json`.
</Note>

Enable the bundle in your `config/bundles.php`:

```php
<?php

return [
    // ... other bundles
    AdUnblock\ServerTag\Symfony\AdunblockServerTagBundle::class => ['all' => true],
];
```

### Basic Usage

The bundle's default tag has no attributes, so it can't carry your Account ID
(`data-code`). Print the tag with a small renderer instead, and make it a Twig
global so every template has it:

```php
<?php
// src/Twig/AdunblockRenderer.php
namespace App\Twig;

final class AdunblockRenderer
{
    /** @param string[] $scripts The script URLs, preferred first. */
    public function __invoke(array $scripts): string
    {
        if (!$scripts) {
            return '';
        }

        // data-cfasync and nowprocket before src: Cloudflare Rocket Loader
        // only skips a script whose data-cfasync comes first.
        return sprintf(
            '<script data-cfasync="false" nowprocket src="%s" async data-code="YOUR_ACCOUNT_ID"></script>',
            htmlspecialchars($scripts[0], ENT_QUOTES, 'UTF-8')
        );
    }
}
```

```yaml
# config/packages/twig.yaml
twig:
    globals:
        adunblock_render: '@App\Twig\AdunblockRenderer'
```

Then in your Twig template, pass your site's domain in the URL and the renderer
as the third argument:

```twig
<!DOCTYPE html>
<html>
<head>
  <title>My Page</title>
  {{ server_tag('https://public.adunblocker.com/api/vendor_scripts?domain=' ~ app.request.host|url_encode, 300, adunblock_render) }}
</head>
<body>
  <h1>My Page</h1>
</body>
</html>
```

The domain lets us move your site alone to a new script host when an ad
blocker rule targets it (see [Fetch Config](/api-reference/fetch-config#query-parameters)).
The cache is kept per URL, so each site of a multi-site install gets its own
answer.

### With Caching

The second argument is the cache duration in seconds (default: `300`, 5 minutes):

```twig
{{ server_tag('https://public.adunblocker.com/api/vendor_scripts?domain=' ~ app.request.host|url_encode, 600, adunblock_render) }}
```

### Function Signature

```php
server_tag(string $url, int $cache_seconds = 300, ?callable $render_script = null): string
```

**Parameters:**
- `$url` (string): The remote URL to fetch scripts from
- `$cache_seconds` (int, optional): Cache duration in seconds. Default is `300`
- `$render_script` (callable, optional): Custom rendering function. Receives an array of script URLs and returns an HTML string. Without it, the tag carries no `data-code`, so always pass one
